# 카드 혜택매니저 v7.4.9 Record Delete & Period Fix

## v7.4.9 핵심 변경
- 실적 히스토리에서 **입력 기록을 개별 삭제**할 수 있습니다.
- 월별·연간 계산에 쓰이는 **최종 반영 기록도 개별 삭제**할 수 있습니다.
- 입력 기록을 삭제하면 같은 카드·같은 기간의 남은 입력값 중 최신값으로 최종 반영이 자동 재계산됩니다.
- 실적기간은 **M BOOST만 24일~다음 달 23일**, **RED와 나머지 카드는 1일~말일**로 고정했습니다.
- 이전 버전에서 잘못 생성된 기록은 자동으로 지우지 않으며, 사용자가 히스토리에서 확인 후 삭제합니다.

기준 베이스: **v7.4.8 Input History & Latest Reflection**

## 삭제 위치
설정 → 히스토리 보기
- `최종 삭제`: 월별·RED 연간 반영에서 제외하며 입력 이력은 유지
- `삭제`: 해당 입력 이력을 제거하고 최종 반영값을 남은 최신 기록으로 재계산

# 카드 혜택매니저 v7.4.8 Input History & Latest Reflection

## v7.4.8 핵심 변경
- 실적 저장 시 **입력 기록은 매번 추가**합니다.
- 같은 카드·같은 실적기간의 **월별 최종 반영값은 최신 저장값으로 갱신**합니다.
- RED 연간 누적은 저장 횟수가 아니라 **실적기간별 최종값 1건만 합산**합니다.
- 기존 중복 데이터는 입력 기록으로 보존하면서 최종 반영 데이터만 자동 정리합니다.

기준 베이스: **v7.4.6 Full Subscription Burden**

## 데이터 구조
- `monthlyRecords`: 카드별·실적기간별 최종 반영값
- `monthlyRecordLog`: 실적 저장 시점별 입력 기록
- 카드/구독 저장소 분리와 전체 구독 부담액 계산은 그대로 유지합니다.

# 카드 혜택매니저 v7.4.6 Full Subscription Burden


## v7.4.6 Full Subscription Burden
- 카드별 현재 실적기간의 전체 구독 부담액을 반영
- 현재 사용금액에 이미 포함된 구독은 중복 계산하지 않도록 보정
- 전체 구독 부담액 / 현재 포함 추정 / 향후 결제액 표시
- 추가 사용 필요액을 전체 구독 예약 기준으로 계산

기준 베이스: **v7.4.4 Subscription Calendar & UI Refine**

## 핵심 변경
- 카드사 앱에서 확인한 **현재 사용금액은 그대로 유지**합니다.
- 실적 입력 시 **금액 확인 기준일**을 함께 저장합니다.
- 기준일 이후, 현재 카드 실적기간 안에 결제될 구독만 **예정 구독**으로 계산합니다.
- 카드별로 **현재 사용금액 / 남은 예정 구독 / 예상 실적 / 추가 사용 필요액**을 분리 표시합니다.
- 기존의 구독 금액 직접 가산 기능은 제거하고 **현재 사용금액 포함 확인** 방식으로 변경했습니다.

## 계산 기준
- M BOOST: 현재 24일~다음 달 23일 실적기간
- RED 및 기타 카드: 현재 월 1일~말일
- 활성 상태이며 연결 카드가 있고 `예정 구독으로 포함`된 구독만 계산
- 결제 예정일이 카드별 현재 사용금액 기준일보다 늦은 항목만 계산
- 이미 `현재 사용금액 포함`으로 확인한 구독은 예정액에서 제외

## 데이터 정책
- 카드 데이터 저장소와 구독 데이터 저장소는 계속 분리합니다.
- 기존 카드 데이터는 유지하며 카드별 `spentAsOfDate`만 추가합니다.
- 자동으로 카드 사용금액을 증가시키지 않습니다.

## 프로젝트 범위
신용카드 사용금액, 실적, 혜택, 구독 결제, 결제 일정, 히스토리, 통계 및 카드 최적화만 다룹니다.
